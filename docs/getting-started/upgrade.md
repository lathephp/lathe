# Upgrade guide

This page is generated from the entries marked `[api]` in the [changelog](changelog.md). It lists only changes to the public API: the classes and methods in the API snapshot, the artisan commands, the config keys, the route names and the JSON contract.

These public API changes happen between 1.0.0-beta.2 and 1.0.0-beta.3. Check each one against your code before you update.

## From 1.0.0-beta.2 to 1.0.0-beta.3

- The testing kit's `DashboardTester` gains `csv()`, `saveLayout()` and `resetLayout()` for the new dashboard routes.
- Each user can save their own layout of a dashboard (order, size and hidden cards) and reset it to the layout in code, through `PUT` and `DELETE` on `api/dashboards/{dashboard}/layout`. A card removed from code drops out of a saved layout, and a new one shows at the end. `Dashboard::customizable(false)` turns it off for a dashboard, and the dashboard payload gains `customizable`, `customized` and a `hiddenWidgets` prop.
- One range picker in a dashboard's header drives every widget on it. `Dashboard::ranges()` sets its options, 7 days, 30 days and 12 months by default, and the page reads the picked one from `?range=`. A widget that does not offer the picked range shows its default range, and its value response names that range as `fallbackRange`; `Widget::defaultRangeKey()` says which range that is. The workbench's Sales dashboard gains Orders per day and Orders by status. On the page the picker is a segmented control beside "Updated ... ago" and Refresh, keeps the pick in the URL, and each card drops its own range dropdown, names the range it fell back to, dims its last value while it reloads and says "<title> could not load" with Try again when it fails.
- A dashboard's trend, bar, partition, pie, radar and table cards download as CSV from `GET api/dashboards/{dashboard}/widgets/{widget}/csv`, with plain numbers and `YYYY-MM-DD` dates; a widget's descriptor gains `csv`. `Widget::link()` sets where a card's Open records goes, and a card whose aggregates read one model links to that model's Resource index for a user who may list it, as `link` in the value response. The bar, partition, pie and radar helpers now apply the host Resource's row scope and tell the cache which tables they read.
- `SelectField::badges()` shows each value as a badge in a tone: neutral, primary, info, success, warning or danger. The workbench's order statuses use it.
- The `@lathephp/ui/popover` and `@lathephp/ui/select` subpaths, so a page can load the popover or the select without the whole kit.
- The config keys `brand.logo` and `brand.logo_dark` put your logo at the top of the sidebar, with a separate image for the dark theme.
- Each user's column choices on a resource index (shown, hidden, order, pinned) are saved on the server in the new `lathe_user_preferences` table, through `PUT` and `DELETE` on `api/resources/{resource}/columns`. A column removed from code drops out of a saved choice, and a new one shows at the end. Run `php artisan migrate` after upgrading.
- `GET api/resources/{resource}/{resourceId}/history/latest` answers a record's newest five action events (who, what and when) for its History card, behind the same `viewAny` of the action log as the Action Events panel.
- A record page's header shows a badge beside the title and one meta line. `ResourceDefinition::recordHeader(badge:, meta:)` names their detail fields: the badge defaults to the first field with badges, and a named meta field shows as "<Label> <value>" in place of the subtitle.
- `ResourceDefinition::phoneCard(title:, badge:, value:, meta:)` names the index columns a row's card shows below 768 px; a slot left out is picked from the index (the record's title, the first badge, the first number and the first relation). `SelectField::hasBadges()` says whether a select shows badges.
- An action's dialog is titled by its confirm text, such as "Mark 3 orders as shipped?", or by the action's name when it has none, and its primary button repeats the action's name. Without `size()` a dialog is 400 px for a confirm and 520 px for an action with fields; the metadata's `size` is then `small` or `medium` where it was `2xl`.
- `:title` in an action's confirm text becomes the record's title when it runs on one record, such as "Cancel order ORD-79186507?": the form route `api/resources/{resource}/actions/{action}/form` takes `resourceId` (404 when the detail query cannot find it) and `Action::confirmTextFor()` takes the title as a second argument. The workbench's Cancel order keeps the order with "Keep order".
- The import dialog shows its steps, File, Map columns, Check and Import, opens 720 px wide, and its check button names the file's rows, such as "Check 2,400 rows"; the upload step's `import:headers-detected` data gains `total_rows`. The edit-conflict dialog's buttons read "Load their version" and "Save mine over theirs".
- `Action::requirePassword()` asks for the user's password before a run unless it was confirmed within `auth.password_timeout`: the run answers 423, and the open dialog shows "Confirm your password" in place of its content, then runs the action after a correct password, so two dialogs never stack. The workbench's Merge tags uses it. `setPasswordConfirmer()` on the panel's internal object now returns the confirmer it replaces.
- `ResourceDefinition::globalSearchSubtitle()` sets the line under a result in the search palette without changing the record's subtitle; the workbench's orders show "Prof. Warren Shields II · Oct 17, 2026 · $1,234.00" and list three per search. Each Resource group in the `api/search` answer gains `count` (`{value, exact, capped, estimated}`, or null when the group shows every match), counted up to 1,000 only when the group has more matches than it shows, and the palette ends such a group with "Show all 20 orders", which opens the index searched for the term.
- At most three toasts show; older ones fold into "N more" and come back as the shown ones close. Queued bulk runs, exports and imports show in that one stack at the bottom right instead of their own panel at the bottom left: a running task's toast stays and updates in place, a plain result closes after 5 seconds, and a result with failures stays, such as "2,388 of 2,400 products imported" with "Download failed rows" under it. `ToastMessage` gains optional `body` and `dismissible`, and an import's status JSON gains `resource_label`.
- Changed English strings since 1.0.0-beta.2, for an app that translates the panel; move each override to its new key: `Run Action` is gone (the primary button shows the action's name); `Mark all read` reads `Mark all as read`; `Override` reads `Save mine over theirs` and the conflict dialog's `Refresh` reads `Load their version` (the dashboard keeps `Refresh`); `Someone else saved this record after you opened it. Refresh to load their changes, or override to save yours over them.` reads `Someone else saved this record after you opened it. Load their version, or save yours over theirs.`; `Validate` reads `Check :count rows`; `Validate the file before importing. Nothing is saved.` reads `Check the file before importing. Nothing is saved.`; `Validating the file…` reads `Checking the file…`; `Download Failed Rows` reads `Download failed rows`; `Runs` is gone (queued runs show in the toast stack); the password dialog's `Confirm password` reads `Confirm your password` (field labels keep `Confirm password`); `Showing :from to :to of :count` reads `:from–:to of :count`; `Showing :from to :to` reads `:from–:to`; `Next` reads `Next page`; `Previous` reads `Previous page`; `All :count rows on this page are selected.` is gone (the selection bar reads `:count selected` and `All :count selected`); `All matching rows selected (:count)` reads `All matching rows selected`; `Select all matching rows (:count)` reads `Select all matching rows`; `Apply` is gone (filters apply as they change).
- Dashboard cards in one row share the tallest card's height, and `height()` is now a minimum. A value card shows every digit on a desktop and a short form on a phone, the change as a signed badge, then "vs" and the earlier value; with no earlier data it says so. `ValueResult::lowerIsBetter()` shows a rise in the destructive colour and a fall in the success colour. The grid gap is 20 px, and below 768 px value cards sit two across.
- The default theme is Lathe's copper design in light and dark. Apps that set `theme.colors` keep their colours. New public tokens: `brand`, `focus`, `skeleton`, `scrim`, `chart-other`, `sidebar-hover`, the tints `primary-subtle`, `success-subtle`, `warning-subtle`, `info-subtle` and `destructive-subtle` with their text colours `primary-subtle-foreground`, `success-subtle-foreground`, `warning-subtle-foreground`, `info-subtle-foreground` and `destructive-subtle-foreground`, and `shadow-xs` to `shadow-lg`. The existing `link` and `link-hover` tokens are copper where they were blue.
- The 16 new colour tokens are `theme.colors` keys and `Lathe\Theme\Color` cases. When an app sets any colour of its own, every token it did not set keeps its value from before copper, so the app keeps its look; `brand` and `focus` take `primary` at 3:1 on the page, and each `-subtle` pair is a tint of its colour with text at 4.5:1.
- Toasts render with Base UI Toast. A toast stays 5 seconds, its timer pauses on hover and focus, and an error stays until it is dismissed. The `@lathephp/ui/sonner` subpath is removed; `@lathephp/ui/toast` replaces it, and sonner is no longer a dependency. `ToastMessage` gains a `timeout` field.
- Date-times read on the 24-hour clock, such as `Oct 17, 2026, 23:12`, where they read `11:12 PM` before.
- The user menu's "Log out" reads "Sign out"; an app that translates the panel moves its `Log out` string to `Sign out`. The menu's trigger shows the email under the name.
- A creatable relation field offers `Create customer "Hanna Vos"` at the foot of its search results. Choosing it opens the related create form in a 480 px sheet from the right with the typed text in the related Resource's title field, and saving selects the new record. The field's payload gains `createTitle`, the related title attribute, or null when the title is a closure.
- A record's detail page has two columns. Its to-many relations are tabs in the main column, each with its count when the field has `withCount()`, followed by a card per wide field; the right column holds a Details card with the other fields, a card per belongs-to, morph-to or has-one record, and a History card with the newest five action events and Show all. The header's badge and meta fields and the title field are left out of Details. Sections, panel limits and field tab groups now shape forms only. The detail payload gains `titleKey`, `counts` and `history`, and the detail page runs one more query, the relation counts.
- `RelationField::modalSize()` is still accepted but no longer sizes anything: the create sheet is always 480 px wide.
- A dashboard card no longer has a range dropdown of its own: the one range picker in the dashboard's header sets every card's range, from `Dashboard::ranges()`. A widget's own `ranges()` now only says which of those ranges it can show.

## What you see

After `composer update lathe/lathe` and the changes above, `php artisan lathe:doctor` ends with `0 FAIL`.
