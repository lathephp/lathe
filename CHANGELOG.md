# Changelog

All notable changes to Lathe are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and Lathe follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The Composer package `lathe/lathe` and the npm packages `@lathephp/core`, `@lathephp/ui` and `@lathephp/vite-plugin` share one version number. An entry marked `[api]` changes the public API; the [upgrade guide](docs/getting-started/upgrade.md) lists them between two releases, with the other entries under Changed as behaviour changes.

## [Unreleased]

### Changed

- [api] The panel home (`/lathe`) sends a user who may not see the main dashboard to the first dashboard they may see, else to the first sidebar page they may open, and answers 403 only when they may open nothing. Sign-in, the brand link and starting or stopping an impersonation land there too. `DashboardController::__invoke()` returns `Response|RedirectResponse`.
- Export and import download links are relative signed URLs checked with `signed:relative`, so a link the queue worker built works at whatever address the panel is opened on, not only at `APP_URL`. A link issued before the upgrade stops working; the next status poll or a new export gives a fresh one.
- In a `dependsOn()` callback, `FormData::get()` returns a `belongsTo` field's key, not the picker's `{value, display}` array, so `Product::find($formData->get('product'))` finds the record. A callback that read `['value']` reads the key directly.
- Value and trend cards offer the dashboard's ranges by default, 7 days, 30 days and 12 months (they were 30, 60 and 365 days, and 30, 60 and 90 days), and still start at 30 days, so a dashboard set to 7 days or 12 months no longer shows "Last 30 days" on its cards. A card with its own `ranges()` is unchanged.
- `TrendResult::transform()` changes the trend's points and series as well as its headline, so `->transform(fn ($cents) => $cents / 100)` plots dollars.
- Extension CSS built through the Lathe Vite plugin imports Tailwind's theme as a reference: `@import "tailwindcss"` defines no `:root` variable that could override the panel's (an app extension turned the panel's Archivo into the system font), and with no `source()` of its own it scans only the CSS file's folder, not the whole app. `@lathephp/core/tokens.css` is a reference theme too. Hand-written CSS in an extension that read one of Tailwind's default variables, such as `var(--color-red-500)`, must define it.
- `Field::heading()` and `Field::hidden()` are compact, so a form draws no label row and no Optional mark for them.
- An action's `->icon('mail')`, a kebab-case Lucide name, draws the same icon as `->icon('Mail')`. `Field::icon()` and a badge's `withIcons()` given a name the field icon set does not draw log one browser console warning that names it; the fields docs list the 27 names the set draws.
- A column's `indexWidth()` holds: its header and cells are that wide at least and at most, where the cells' 320 px cap could widen it before.
- A list with no inline-editable cell, such as Action Events, follows a link in a cell, such as a related record's name, on the first click and still moves the cell cursor there. A list that edits inline keeps the beta.5 rule: the first click moves the cursor and the link opens once its cell holds it.
- The trashed-only view of a soft-deleting list (`trashed:only`) draws no Soft Deleted badge, since every row in it is deleted; a view that mixes live and deleted rows keeps it.

## [1.0.0-beta.5] - 2026-10-28

### Added

- `php artisan lathe:preset copper` writes the copper colours of 1.0.0-beta.4 and the `0.625rem` radius into `config/lathe.php`, with no request, for an app that wants its old look back. A bare `lathe:preset` lists it.
- [api] Each filter in the index payload's `filters.available` carries `token`, its key in the filter bar, and `kind`, the value that key takes: `select`, `multiple`, `range`, `date`, `boolean`, `relation` (a remote picker) or `text`. The token is the filter's `key()`, except that a `filterable()` field's filter goes by its label in snake case (`total` for Total) unless that clashes with another filter's key.
- [api] Each saved tab in the index payload's `tabs.saved` carries its search as `q`, and `filters.labels` names the remote values of the saved view `?saved_tab=` opens, so the filter bar draws an open saved view's filters and search as its chips and text; changing one leaves the view and writes every chip to the URL.
- [api] A select opts into a status meter with `meter(except: [...])`. The payload carries the tick values as `meter`, and a meter with fewer than 2 or more than 5 ticks throws a `LogicException` naming the field when `fields()` builds. The workbench's order status leaves Cancelled out of the ticks:

  ```php
  Field::select('Status')
      ->options(['pending' => 'Pending', 'paid' => 'Paid', 'shipped' => 'Shipped', 'cancelled' => 'Cancelled'])
      ->meter(except: ['cancelled']);
  ```

- [api] `->board('<field>')` on a Resource's definition shows its list as a Board too, one column per option of that index field in declared order, plus a No value column when the field is nullable. The field must be an inline select with at most 12 inline options; anything else throws a `LogicException` naming the field when the Resource boots, and a subclass that drops the field calls `->board(null)`. The index payload carries `table.board`, `{field, noValue}`, or `null` on a lens, without a board, or when the user cannot see the field.

  ```php
  return $definition
      ->model(\App\Models\Order::class)
      ->board('status');
  ```

- [api] A list with a board opens in the layout its URL names, `?layout=board` or `?layout=table`, else in the one the user chose last on that Resource, else as the table. `PUT .../resources/{resource}/layout` with `{layout}` saves the choice per user (404 for a Resource without a board), and the index sends the layout it opened in as `table.layout`, always `table` on a lens or without a board.
- [api] `GET .../resources/{resource}/board?column=<option>&page=<n>` returns `{rows, hasMore}`: one page of 25 cards of a Board column, each row shaped as in `table.rows`, in the list's sort. `&offset=<n>` in place of `page` starts at that card, which the Board's Show more sends so a card moved out of the column skips none. An empty `column` is the No value column, allowed on a nullable field; an unknown column, a bad page or offset, or one at the count cap or past it is 422, and a Resource without a board is 404. `GET .../board/counts` returns `{columns: [{value, count}]}`, one capped count per column in option order with `null` last on a nullable field. Both read the index's own query keys (`filter`, `q`, `tab`, `saved_tab`, `sort`).

### Changed

- [api] `GET .../{id}/preview` serves the preview panel. With an empty `fieldsForPreview()` it returns the record's detail fields without its relation lists (a BelongsTo or MorphTo name stays), so every Resource has a preview; `showOnPreview()` no longer narrows it, a field marked `showOnPreview()` or `onlyOnPreview()` joins it, and `hideFromPreview()` still drops a field. The reply adds the record's `abilities` and its detail `actions`. Each user's panel is open or closed per Resource: `PUT .../resources/{resource}/preview-panel` with `{open}` saves it, and the index sends it as `table.previewOpen`. The preview modal and the row's Preview button (the English string `Preview :title`) are gone, with the index's `resource.preview` flag: Space opens the panel on the cell cursor's row, `clickAction('preview')` opens it on the clicked row, and `TagField::withPreview()` opens it over the page. On a phone a tap on a list's card opens the panel full screen in place of the record's page; Ctrl or Cmd with the tap still opens the page.
- [api] An app with no colours of its own opens in the new identity: steel neutrals, the layout blue primary (`#2e47e0` in light, `#8796ff` in dark), the teal `info`, and an 8 px panel radius. The 56 token names keep their names and meaning; only their default values change. An app that sets any colour keeps its look. To keep copper, run `php artisan lathe:preset copper`.
- [api] `theme.radius` defaults to `0.5rem` (was `0.625rem`). A published `config/lathe.php` keeps the radius it lists; set it to `0.5rem` for the new corners.
- [api] The bundled typeface is Archivo, with its width and weight axes in the latin and latin-ext subsets, in place of Inter Variable. `theme.font` set to `null` uses it; page and record titles and widget values use its 122% width.
- A resource index lists its views in a 220 px rail at the card's left, in place of the tab band: the developer tabs, then the user's saved views (Save view, rename, delete, and reorder by dragging or with Alt+Up/Down), then the lenses. Tabs and saved views keep their deferred, capped counts; lenses show none. Below 1100 px, or while the preview panel sits beside the card, the rail folds into a Views menu at the start of the toolbar, which opens the same list. Saved tabs carry over as views unchanged.
- A resource index and its lenses filter from one bar above the table, in place of the search box, the Filter button with its popover, and the chip row under the toolbar. Type `status:pending,paid`, `total:>1500`, `total:10..50` or `customer:"Ann Taylor"` and press Enter: each token becomes a chip that writes the real `filter[...]` keys (`trashed:with` or `trashed:only` the `trashed` key), plain words search as `q` did, and a token that cannot apply shows as a red chip with its reason, such as "No filter named statuz", without changing the rows. A chip change sends one visit 300 ms after the last; Backspace in the empty input removes the last chip, Left arrow reaches the chips and `/` focuses the bar. A reload or a shared link draws the same chips from the URL. A click on the bar lists the Resource's filters, and typing the start of one's name or key (`sta`) narrows the list to it; choosing a filter puts its key in the input and lists its values (a relation's from its options search, a range, date or text filter its grammar), and choosing a value adds the chip. Up and Down move through the list, Enter picks the highlighted item and Escape closes it. Relation tables keep their search box and filter panel.
- [api] Changed English strings since 1.0.0-beta.4, for an app that translates the panel; move each override to its new key: `Tabs` reads `Views` (the views rail and the Views menu). `Filter`, `:count :resource` and `Show :count :resource` are gone with the index's Filter popover; the filter bar of a Resource that cannot search is named `Filter :resource`. `Edit :field` is gone now that a cell opens its control from the keyboard, and `Preview :title` with the row's Preview button. New strings to translate: `:filter has no option :value`, `:filter takes a date as YYYY-MM-DD, >date, <date or a..b`, `:filter takes a number, >n, <n or a..b`, `:filter takes any text`, `:filter takes one value`, `:filter needs a value`, `:filter takes yes or no`, `Arrow keys`, `Board`, `Change undone`, `Clear the selection`, `Double-click`, `Edit a cell`, `Extend the selection`, `Go to the row's first or last cell`, `Keyboard shortcuts`, `Layout`, `Move 25 rows`, `Move the cell cursor`, `Move :title`, `Move to`, `No :filter matches :value`, `No :resource`, `No filter named :key`, `No value`, `Open full page`, `Open the row, on a cell that cannot be edited`, `Preview the row beside the list`, `record`, `Save and move right`, `Select`, `Select all matching`, `Select the page`, `Select the row`, `Show more`, `Show this sheet`, `Space`, `Table`, `This :resource was deleted.`, `Trashed takes with or only`, `Undo the last cell edit`, `You may not view this :resource.`.
- A Resource with `->board()` lists as a Board too: a Table/Board switch beside the filter bar shows one column per option, each headed by the option's meter or badge and its count capped at 10,000+, with 25 cards and Show more; a card shows its phone card's title, badge, value and meta. The Board follows the filter bar, the search and the open view, and stays chosen per user and in the link (`?layout=board`). Drag a card to another column, press Shift+Left or Shift+Right on it, or use its Move to menu: the field saves as its inline edit does, both counts change, a refused move goes back with the reason, and Ctrl/Cmd+Z or the toast's Undo takes it back. The arrows move between cards, Space or a click opens the preview panel, and the Board selects nothing. A phone and a lens show no Board. New English strings: `Board`, `Table`, `Layout`, `No :resource`, `No value`, `Show more`, `Move :title` and `Move to`.
- Table rows are 40 px tall at the comfortable density (was 48 px), and the nova style's default buttons, inputs and selects are 32 px (was 34 px).
- [api] Every Resource list, lens and relation table is a grid with one tab stop and a cell cursor: a click on a cell moves the cursor and no longer opens the row, and a link in a cell, such as a related record's name, opens once its cell holds the cursor, so a link in another cell takes two clicks; the arrows, Home, End, Page Up and Page Down move it. `clickAction` now names what Enter on a cell that cannot be edited, or a click on the title cell, does. An inline cell shows its value until Enter, F2 or a double-click opens its control, so the English string `Edit :field` is gone; Tab saves and moves right, Escape cancels, a refused value stays open with the server's message, and a stale save opens the conflict dialog. Ctrl/Cmd+Z, or the toast's Undo, undoes the last cell edit made in the tab; running an action empties that history. Undo covers cell edits and Board moves only: an action, a delete or a form save cannot be undone. X, Shift+Up/Down and Shift+click select rows, Escape clears them, and `?` on a list, or Keyboard shortcuts in the user menu, lists the keys. The row abilities gain `inlineEdit` when a column edits inline, relation rows carry `updatedAt`, and Load more stops at 100 rows, where a pager takes over.

### Fixed

- [api] `filterable()` on a select field that names no `$options` lists the field's own options as a select filter, as `filterable(options: [...])` does, where it gave a range filter that took only numbers, so `status:review` in the filter bar was a red chip. A select with remote options keeps the range filter. `SelectField::makeFieldFilter()` builds it.

## [1.0.0-beta.4] - 2026-10-19

### Added

- [api] A `shell.header` replacement gets the page's `breadcrumbs` and a `pageBarRef` for the phone's page title and main action, now that the default top bar carries both; without a page bar, a page keeps its title and main action on a phone.
- [api] The `@lathephp/ui` Button gains the `destructive-solid` variant for a confirm dialog's button, and `destructive` turns outlined in the nova style; Badge gains `success`, `warning` and `info`. Every style draws them.
- [api] `ProgressResult::tone()` keeps a progress bar in one colour (primary, info, success, warning or destructive) at any percentage, for a share that measures a state rather than a goal, and `ProgressResult::label()` replaces the words after the share. The workbench's Shipped card uses both.

### Changed

- The panel follows the approved design throughout. The sidebar has uppercase group headings that fold, and the top bar carries the breadcrumb and a "Search or jump to…" button. Every page has a one-row header with its actions on the right, such as an index's "Create order". Tables have a muted header row, 48 px rows (56 px when spacious), status badges that open inline edit, related names in the text colour and ghost toolbar buttons. Forms sit in cards with "Optional" beside the fields that may stay empty, in place of a mark on the required ones, and a sticky footer. Record pages, dashboards, dialogs, toasts, notifications and the search palette follow their boards, and a phone keeps a 12 px gutter. Only the default nova style changes; the other styles keep their look.
- [api] Changed English strings since 1.0.0-beta.3, for an app that translates the panel; move each override to its new key: `Create & Add Another` reads `Create and add another`, and `Other` reads `:count more` (the rest row of a pie drawn as bars, such as "15 more"). `Create :resource` keeps its key and fills in the resource name in sentence case, so the create form's title, crumb and button read "Create order"; a translation that starts with the name, or a language that capitalises nouns, writes `:Resource`.

## [1.0.0-beta.3] - 2026-10-19

### Added

- [api] The testing kit's `DashboardTester` gains `csv()`, `saveLayout()` and `resetLayout()` for the new dashboard routes.
- [api] Each user can save their own layout of a dashboard (order, size and hidden cards) and reset it to the layout in code, through `PUT` and `DELETE` on `api/dashboards/{dashboard}/layout`. A card removed from code drops out of a saved layout, and a new one shows at the end. `Dashboard::customizable(false)` turns it off for a dashboard, and the dashboard payload gains `customizable`, `customized` and a `hiddenWidgets` prop.
- [api] One range picker in a dashboard's header drives every widget on it. `Dashboard::ranges()` sets its options, 7 days, 30 days and 12 months by default, and the page reads the picked one from `?range=`. A widget that does not offer the picked range shows its default range, and its value response names that range as `fallbackRange`; `Widget::defaultRangeKey()` says which range that is. The workbench's Sales dashboard gains Orders per day and Orders by status. On the page the picker is a segmented control beside "Updated ... ago" and Refresh, keeps the pick in the URL, and each card drops its own range dropdown, names the range it fell back to, dims its last value while it reloads and says "<title> could not load" with Try again when it fails.
- [api] A dashboard's trend, bar, partition, pie, radar and table cards download as CSV from `GET api/dashboards/{dashboard}/widgets/{widget}/csv`, with plain numbers and `YYYY-MM-DD` dates; a widget's descriptor gains `csv`. `Widget::link()` sets where a card's Open records goes, and a card whose aggregates read one model links to that model's Resource index for a user who may list it, as `link` in the value response. The bar, partition, pie and radar helpers now apply the host Resource's row scope and tell the cache which tables they read.
- [api] `SelectField::badges()` shows each value as a badge in a tone: neutral, primary, info, success, warning or danger. The workbench's order statuses use it.
- [api] The `@lathephp/ui/popover` and `@lathephp/ui/select` subpaths, so a page can load the popover or the select without the whole kit.
- [api] The config keys `brand.logo` and `brand.logo_dark` put your logo at the top of the sidebar, with a separate image for the dark theme.
- [api] Each user's column choices on a resource index (shown, hidden, order, pinned) are saved on the server in the new `lathe_user_preferences` table, through `PUT` and `DELETE` on `api/resources/{resource}/columns`. A column removed from code drops out of a saved choice, and a new one shows at the end. Run `php artisan migrate` after upgrading.
- [api] `GET api/resources/{resource}/{resourceId}/history/latest` answers a record's newest five action events (who, what and when) for its History card, behind the same `viewAny` of the action log as the Action Events panel.
- [api] A record page's header shows a badge beside the title and one meta line. `ResourceDefinition::recordHeader(badge:, meta:)` names their detail fields: the badge defaults to the first field with badges, and a named meta field shows as "<Label> <value>" in place of the subtitle.
- [api] `ResourceDefinition::phoneCard(title:, badge:, value:, meta:)` names the index columns a row's card shows below 768 px; a slot left out is picked from the index (the record's title, the first badge, the first number and the first relation). `SelectField::hasBadges()` says whether a select shows badges.
- Index filters apply 300 ms after the last change, with no Apply button. The Filter button opens a popover with the live match count in its foot, shows how many filters are set, and every set filter shows as a chip with a remove button under the toolbar. `Filter::labels()` names the values a remote filter holds for its chip; a filter over a large table overrides it with a lookup of those values.
- Sidebar links and a table row's first cell fetch their page after a 75 ms hover and keep it 30 seconds; any write to the resource drops it. A click shows the next page at once: the sidebar item turns active on press, and if the data has not come after 100 ms the page shows its title and a skeleton of its layout.

Cancel and the save buttons sit in a footer stuck to the bottom of the window, which shows "Unsaved changes" while the form holds unsaved values; leaving the page then asks first.
- A failed save scrolls to a summary that links each field needing a change, in the error colour, and focuses the first; a field's error clears as soon as it changes. A readonly field shows on a muted ground with a dashed border, and any other disabled control is dimmed.
- A field shown by `visibleWhen()` sits on its own row under its parent, on a muted ground, with the reason, such as "Shown because Type is Company".

### Deprecated

- [api] `RelationField::modalSize()` is still accepted but no longer sizes anything: the create sheet is always 480 px wide.

### Removed

- [api] A dashboard card no longer has a range dropdown of its own: the one range picker in the dashboard's header sets every card's range, from `Dashboard::ranges()`. A widget's own `ranges()` now only says which of those ranges it can show.

### Fixed

- `lathe:doctor` checks the `lathe_user_preferences` table, so an app that updated without running `php artisan migrate` gets a FAIL there instead of 0 FAIL and a broken index.
- On a phone, the open menu has a Close menu button and closes on Escape, and the user menu closes on a click outside it.
- A record's breadcrumb names it by its title instead of `#id`; the id stays only when the title is empty.
- When a queued bulk action, delete or restore ends, the index it ran on reloads its rows in place.

## [1.0.0-beta.1] - 2026-10-16

The first public release of Lathe, an admin panel builder for Laravel on Inertia, React and shadcn/ui. MIT licensed.

### Added

- Resources: discovery from `app/Lathe/Resources`, the index with search, filters, sorts, lenses, saved tabs, column summaries and row grouping, capped counts that stay fast on tables with millions of rows, detail and form pages, inline edits and peeks.
- Fields: text, number, date, choice, file, image, rich text, Markdown, code and key-value fields and more, with validation, visibility rules, computed values and utility injection, relation fields with pickers, pivots and repeaters, and chunked uploads.
- Actions: single, bulk and queued actions with progress, CSV and Excel export and import with a dry run, and an audit log of every run.
- Dashboards: value, trend, progress, table, help, custom, bar, pie, partition, radar and radial widgets, on dashboards, Resources and lenses.
- Customising: menus, standalone pages, plugins with settings, resource plugins, 8 theme styles with dark mode and right-to-left, keyboard shortcuts and a command palette.
- Accounts: sign-in, password reset, email verification, two-factor authentication, password confirmation and impersonation through Laravel Fortify; policies that deny by default.
- Tooling: `lathe:install`, `lathe:doctor`, the `lathe:*` generators, a testing kit, a Laravel Boost skill and the public API snapshot checked by `lathe:api-check`.
